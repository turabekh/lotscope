## 3. The fix that was wrong

`run_loader` records a failure in its own session, by design, so the loser of a concurrent duplicate ingest clobbered the winner's success and the ops board read red for a healthy dataset. #173 guarded the failure write on `last_success_at < run_started_at`.

**`func.now()` is `transaction_timestamp()`** — frozen at the transaction's first statement:

```
begin;
select now(), clock_timestamp();   -- 23:10:05.935833 | 23:10:05.941991
select pg_sleep(2);
select now(), clock_timestamp();   -- 23:10:05.935833 | 23:10:07.950034
```

**No loader commits mid-run** — zero `.commit()` calls under `ingestion/loaders/`, only flushes — so a whole load is one transaction and `last_success_at` recorded when the winner *started*. The guard then failed in exactly the incident shape: nightly begins 22:00 and commits at 22:40 stamped `22:00`, the manual run begins 22:05 and fails at 22:50, `22:00 < 22:05`, clobber proceeds. Only the ordering where the *loser* started first was protected — and the later starter is the likelier loser.

**The test was the real failure.** It recorded the competing success from a *freshly opened* session, whose transaction began after the start stamp — the one shape where the guard works. It went red without the fix and green with it, and proved nothing. Production records success from the run's own long-lived transaction. Same family as CLAUDE.md §12's "a test that builds its own staging row", but about **timing shape** rather than data shape: ask which transaction each timestamp comes from and whether that matches production's session lifecycle.

`clock_timestamp()` fixed it, and incidentally corrected a pre-existing inaccuracy — `evaluate_freshness` computes `age = now - last_success_at`, so every dataset had been reporting itself one full run-duration staler than it was.

## 4. The vacancy correction, measured

`VACANT_LAND_USES_BY_MARKET` registered `hbg` and `pgh` only. Philadelphia never derived vacancy from OPA land use — 14,020 of 42,583 OPA-vacant parcels carried no flag, 77% of `VACANT LAND - RESIDENTIAL`.

**The derivation is additive and never writes `false`.** `hbg`/`pgh` have no Vacant Property Indicators equivalent, so derivation is their sole source there. Philadelphia has VPI, and the two disagree both ways: **9,150 parcels are VPI-vacant that OPA does not call vacant land.** Copying the other markets' pattern would have silently un-flagged all 9,150 *and still reported the same row count*. ADR-0084.

| | before | after |
|---|---|---|
| flagged vacant | 37,881 | **51,633** (+13,752, the predicted count exactly) |
| VPI-only parcels | 9,150 | **9,150 — no regression** |
| flagged despite a structure | — | **0** |
| phl leads ≥30 | 38,583 | **41,621** (+3,038) |

**Cache invalidation caught one real thing.** Of 17 cached AI artifacts, exactly one was stale: `summary:parcel-summary-v2:phl:191357500:v11` — **2138 N FAIRHILL ST, one of the trial user's six lots**, whose cached text called her lot not vacant. Purged. Without §12's within-version rule the most likely reader of that page would have had stale text about her own property for seven days.

**No version bump.** `is_vacant` reaches the verdict engine only as batch scope; the rule it feeds was already live in `philly-distress-v2`.

## 5. Public ownership — closed the same session (interim)

`is_city_owned` was set for `pgh` (8.7%), `hbg` (4.6%) and `wlm` (0.12%) and for **1 phl parcel of 588,606**, so every behaviour it gates — distress zeroing, the `public_ownership` risk flag, saved-search, watchlist and distress-list exclusions, assemblage candidacy — was inert in the flagship market.

**The authoritative source does not exist upstream** (§6 stands unchanged on that). PR #181 therefore derives it from the OPA owner name, **explicitly interim**, per ADR-0085.

The pattern shape is load-bearing and was measured, not guessed: `PHILADELPHIA HOUSING` must anchor or private `HLP PHILADELPHIA HOUSING` matches; `LAND BANK` must not anchor or the upstream misspelling `PHIADELPHIA LAND BANK` is missed; the `LLC` exclusion is what separates `PHILADELPHIA HOUSING AUTHORITY` from `PHILADELPHIA HOUSING GROUP LLC`, which anchoring alone cannot. Naive patterns matched 13,434; the rule matches **13,426**, excluding exactly the three private owners found by inspecting the owner strings first.

**Unlike vacancy this writes `false` as well as `true`,** because ownership has one truth rather than two complementary sources. Market scope is what makes that safe — the query *and* the UPDATE both pin `phl` — and it is the thing to check if this is ever touched again.

| **market isolation** | hbg **905**, pgh **12,497**, wlm **32** — all identical to baseline |
| targeted verdict recompute | 13,426 / 13,426, all now carry `public_ownership` |

| phl distress | before | after |
|---|---|---|

**No version bump** — v11 methodology receiving correct input, the same posture as #168 and ADR-0084. The targeted verdict recompute is what keeps stored rows honest, since lazy recompute fires only on version mismatch and no version moved.

**Revisit if a real source is adopted.** OPA ownership is stale on some parcels (0047 §5 records `3862 ASPEN ST` still naming a 2025 seller), so this derivation would write `false` over an authoritative flag. It must become additive or be retired at that point — the same lesson ADR-0084 already encodes for vacancy.
