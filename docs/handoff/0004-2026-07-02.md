## Open decisions / tracked follow-ups (recorded in `redesign-roadmap.md`)

- **Explore list ordering** — the viewport list is top-200-**by-score**, not representative; the
  honest label ("showing top N") must not become a permanent cover. Queue representative
  ordering / paging.
- **Saved-search true match count** — matches cap at storage (`MAX_MATCHES_PER_SEARCH=500`) and
  `match_count` counts stored rows; a search matching >500 shows 500 as total. No cheap true
  total (needs an uncapped criteria `COUNT` threaded through `SavedSearchDetail`/`Item` + FE
  "showing top 500 of N"). Deferred — high cap, common case exact.
- **Opportunity-score quantization** (verdict-model, post-redesign, ADR-level): 71% of parcels
  sit at exactly `62` (42%) or `92` (29%); the score chip can't differentiate dense-area lots.
  A separate investigation of the scoring/binning in the verdict engine (ADR-0007). **Not** a
  display bug — confirmed the list reads the real per-parcel v5 score.
- **Compare/Pipeline parcel-open → dossier route:** SavedSearches done (5a); Compare in 5b;
  Pipeline in 5c.
- **Public per-market dataset-freshness surface** (from Slice 2): the `DataCoverageChip` is a
  static provenance label until this backend surface exists.
- **MapView resize nudge (declined):** toggle/drawer resize relies on MapLibre's built-in
  `ResizeObserver` (no window-resize listener). If a toggle lag ever bothers, the only clean fix
  is a 1-line `defineExpose({ resize })` on MapView called from ExplorePage — deliberately not
  added to keep MapView untouched.
