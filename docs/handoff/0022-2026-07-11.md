### Harrisburg buildability by-right (`65b9190`)
Two slices; buildability required *both* a permitted use *and* dimensional conformance, and hbg had
neither wired.
- **`f5dd5f7` — provisional permitted-uses.** hbg zoning standards hardcoded `permitted_uses=[]`. Encoded
  a per-district use list (`zoning/seed_hbg.py::_PERMITTED_USES`) from the authoritative **§7-305.4
  district purpose statements** (the granular §7-305.7 P/SE table is a separate eCode360 attachment not in
  hand — the uploaded Title-7 PDF has the header + P/SE legend but the grid didn't extract). RL→single;
  RM→incl. multi-family; CN/CG/DC→commercial+residential; INS→institutional; IND→commercial+industrial;
  RF→restrictive single/two-family; OSR→parks/recreation. Provenance string notes it's provisional. Stays
  under the `hbg-provisional-2026` cap + 25-parcel reviewer sign-off.
- **`e8f3546` — derive lot width from geometry.** hbg parcels carry no frontage, so even with uses,
  `_check_conformance` couldn't verify width → most lots stayed "uncertain". `derive_hbg_lot_width` sets
  `frontage_ft` = short side of the parcel's `ST_OrientedEnvelope` (geom_local is EPSG:2272 ft) where
  null. Registered as the hbg **`dimensions`** console job.
- **Verified locally end-to-end** (re-seed + dimensions + recompute): vacant hbg **by-right 8→575**,
  **uncertain 823→0**, rest correctly needs-variance (genuinely below the area/width minimum).
