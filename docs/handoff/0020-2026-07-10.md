## What shipped to `origin/main`

### `feat/hbg-flood-loader` (`affb520`) — deployed · graduation gap #3
`load_hbg_flood` (in `ingestion/loaders/hbg.py`) reads the **city** GIS hub `Flood_Parcels` layer
(`CITY_ARCGIS` = services5, NOT the county services2 in the market config) — parcel polygons pre-tagged
`floodzone` (`100 Year` = SFHA, `500 Year` = 0.2%). Keeps the non-`N/A` polygons as hbg `FloodZone` rows
(`external_id = hbg:flood:{oid}`, namespaced off phl). **Reuses the existing spatial `ST_Intersects` risk
join — zero risk/verdict code change, no parcel-key reconciliation.** Registered as the hbg `flood` job →
auto-appears in the console. Promoted `hbg._CITY_ARCGIS` → public `CITY_ARCGIS`. Verified live through the
console against the real hub: **3,200 flood polygons, 3,246 hbg parcels flagged** (zones 100/500 Year).
**Deployed** (run `29094280980`, green).

### `fix/risk-coverage-note-parcel-market` (`891d052`)
A phl parcel viewed while the Harrisburg market was active showed *"Risk based on available Harrisburg
sources"* — `VerdictHero`/`VerdictPanel` read `market.activeInfo` (the switcher) instead of the parcel's
market. Now derive the parcel market from its `parcel_number` prefix (`marketCodeFromParcelNumber`) + a new
`market` store `infoByCode()` getter. Regression test covers the exact leak. Frontend-only.

### `fix/map-tiles-relative-url` (`8f30c94`) — the "no markers" bug
MapLibre can't construct a `Request` from a **relative** tile URL (`Failed to parse URL from
/tiles/parcels_mvt/...`). When `VITE_MARTIN_URL` is unset (local dev), `martinUrl` defaulted to `/tiles`
(relative) → **parcel/marker tiles never loaded on local**; prod set an absolute URL so it was masked
there. Fix: `absoluteTileBaseUrl(raw, origin)` resolves a relative value against `window.location.origin`
(the `/tiles` Vite proxy still applies, same-origin). +2 regression tests. Frontend-only.
