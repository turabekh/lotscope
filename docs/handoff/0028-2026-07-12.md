## The two efforts in detail

### A. Live CivilView sheriff source (PRs #1–3)

- Upstream = `salesweb.civilview.com` (`countyId=60`). One GET returns the whole ~1,500-row county list;
  each row's detail page is fetched **primed by a session cookie the list response sets** (detail pages 302 to
  home without it). Robots: no `robots.txt` (404); scrape is low-volume and ToS-honoring.
- **Selected by `SHERIFF_SALE_SOURCE`** (`csv` default/fallback, `civilview` live). Pure fixture-tested parsers
  (`selectolax`); everything downstream (staging→merge→events→API→frontend) was already built.
- Live-verified: ~1,483 unique OPAs from the list, **~97% reconcile** to loaded phl parcels.
- **Admin coverage button** on the Ops dashboard measures that reconciliation rate on demand (against whatever
  DB the app is on → prod coverage on demand).

### B. Deal-closing batch (PRs #4–9)

Recon (ADRs 0061–0063) reshaped the batch with two findings:
- **F3 was already shipped** (the CivilView scraper above), so its slice collapsed to **hardening only** — no
  rebuild, and a deliberate decision **against sale-month list paging** (ADR-0063).
- **F1 is phl-only**: `sale.grantee` fill is phl 100% / pgh 0% / hbg 0%. hbg/pgh return an honest unavailable
  state; grantee backfill is a follow-up.

**F1 — cash-buyer / disposition intelligence (Investor tier).** Derived entirely from `sale.grantee` we already
hold. A `buyer_profile` table (GiST on `activity_centroid`) fed by a **nightly post-ingest derivation** that
applies four arm's-length exclusions — related-party tokens (ADR-0032), package deeds (ADR-0049), nominal price,
government/Land-Bank names — normalizes grantee → `buyer_key`, aggregates stats + an activity centroid,
best-effort-joins a mailing address via `owner_key`, upserts qualifiers and revokes those that age out.
**~104 active phl buyers** at the confirmed threshold (≥3 arm's-length vacant-lot purchases / 24 months / 0.5 mi).
Three Investor-gated, market-predicated reads (near-parcel, roster, profile); per-market name gate is data-driven
(`buyers` hidden for pgh). Frontend: `/:market/buyers` roster + buyer profile + "Active lot buyers nearby" dossier
panel + Investor CSV export.

**F2 — offer / letter-of-intent generation (Pro+).** The deterministic core of CW-3 with **no AI**. `reports/loi.py`
(`compose_loi` pure + `render_loi_pdf` reusing the dossier fpdf2 scaffold + `appeal_packet._comp_table`).
`POST /pipeline/{parcel}/offer` streams a non-binding LOI at the stored `max_allowable_offer`, with a
comp-evidence appendix carrying the valuation exclusion notes verbatim. **Missing economics → 409** two-path;
**manual-price path** renders without MAO framing and stamps "user-supplied" provenance. Persists an
`offer_generated` `deal_activity` entry (params + comp fingerprint); adds the parcel to the pipeline if absent
(no new table). `app_user` signer fields + `PATCH /auth/signer`. Frontend: `GenerateOfferDialog` launched from the
dossier Deal-analysis panel and the pipeline deal-card menu; Settings signer form.

**F3 — sheriff hardening.** `load_sheriff` now counts fetched-but-dropped rows and surfaces the tally
(`sheriff_load_complete` log + `dataset_freshness.detail` = "N of M rows skipped"). Added the POSTPONED
status-transition test and a missing-opening-bid detail-parser test.

## Gotchas discovered this session

- **CivilView detail pages 302 without a session cookie** primed by first hitting the list page.
- **`buyer_profile.activity_centroid` SRID must match parcel `geom_local` (2272), not 0** — thread `ST_SRID`
  through, else `ST_DWithin` errors on mixed SRID.
- **Autogenerate migrations carry pre-existing noise** (staging/raw tables, geometry reflection diffs) — hand-trim
  to only the additive change (both migrations this session were hand-authored/trimmed).
- **Frontend `pnpm typecheck` runs the whole project incl. specs** — stricter than `vue-tsc -p tsconfig.json`;
  type test mocks (`vi.fn<(a,b)=>ret>()` single-generic form in vitest 2.1).
- **`deal`/`deal_activity` are not autogenerate-managed** (established gotcha) — F2 reused `deal_activity.kind`
  rather than migrating.
