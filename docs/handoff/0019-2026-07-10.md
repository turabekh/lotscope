## What shipped to prod this session (ADR-0059)

Three slices, each its own merge, all now live on `parcelphl.online`:

### 1. Browser job console (`bb5d191`) — migration `d3b9f1c72a48`
Admin-only console to trigger ingestion + recompute jobs server-side via ARQ.
- **New `job_run` audit table** (job id, kind, market, arq job id, status queued/running/success/failed,
  timing, result count, error, **triggered_by**). Provenance for every triggered run.
- **`admin/catalog.py`** — a whitelist `JobSpec` catalog built from `INGEST_JOBS` (market × dataset) + the
  recompute jobs. The API accepts a catalog `job_id` only — no arbitrary callable, args constrained to the
  catalog's own coordinates (keeps a remote-trigger surface from being an RCE surface).
- **Async via ARQ**: API opens an arq pool (`app.state.arq_pool`); `POST /admin/jobs/run` enqueues
  `run_admin_job(job_run_id)`; the worker wrapper marks running, dispatches via the catalog, records
  success/failure (**no auto-retry**). A second run of a job already queued/running → 409.
- Endpoints (all `require_admin`): `GET /admin/jobs`, `POST /admin/jobs/run`, `GET /admin/jobs/runs`.
- `AdminPage.vue` Jobs section: Run buttons grouped by market/kind + a run-history table that polls.
- A test keeps the catalog and worker dispatch in sync so drift fails CI.

### 2. Parameterized jobs + HBG tax-claim (`770a91a`) — migration `e5a1c8b0f2d9`
- `JobSpec` gained a typed `params` schema; `PARAM_INGEST_JOBS` registry holds jobs that take runtime
  inputs; `job_run.params` (JSONB) records what an operator supplied.
- Registered **`hbg tax_claim`** (the previously-orphaned `load_hbg_tax_claim`), params **list_url +
  list_date**. The Dauphin upset/judicial list is reachable from the prod VM, so it can now be pulled
  from the browser. UI shows a **"Run…"** button that opens a parameter dialog.
- `POST /admin/jobs/run` validates params against the spec (required present, dates parseable).

### 3. Server-side source puller (`0829c47`) — no migration
- `GET /admin/fetch?url=` (admin-only) fetches a URL **server-side** and streams the raw bytes back as a
  **browser download** — no ingestion, no DB, no scp; the file lands in local Downloads. Chosen over
  save-to-disk because the api/worker containers have **no shared data volume** (code is baked into the
  image). `GET /admin/fetch/sources` lists known-source shortcuts.
- `AdminPage.vue` "Pull data from the server" box: URL field + Pull + clickable source chips (Dauphin
  repository PDF, city GIS catalog, historic + neighborhood GeoJSON). http(s)-only; full in-memory fetch,
  so it targets modest files (exports, GeoJSON, PDFs), not bulk mirrors.
- Promoted `hbg._CITY_ARCGIS` → public `CITY_ARCGIS` for the shortcut URLs.
