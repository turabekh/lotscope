## 3. The disclosure, and the half a fix

Anonymous, against production:

```
GET /api/search?q=FAIRHILL&market=philadelphia   -> 200  "owner":"NUTMAN ALEXANDER JOSEPH"
POST /api/search/area                            -> 200  full result page
```

`CLAUDE.md` §13 restricts owner PII by role. Nothing enforced it. `/search/area` compounded it: arbitrary GeoJSON polygon, `limit` up to 500, a reported `total` to page against, and **no rate limiting anywhere** — not in the app, not in Caddy. Roughly 1,200 unauthenticated requests to mirror Philadelphia.

**Requiring auth was not sufficient and it is important to be clear about why.** `POST /register` is public, so the vector reopened for the cost of a signup. #189 counts **distinct parcels disclosed per user per day**, not requests — `/search/area` fires on every map `moveend` behind a 350ms debounce, so a request cap would break panning while barely inconveniencing a scraper, whereas re-panning a neighbourhood adds almost no new distinct parcels and systematic tiling adds a full page every call. Free 10,000/day, pro 100,000, investor and enterprise unlimited. It reuses `register_parcel_view`'s existing Redis-set shape and `QuotaExceededError`'s existing 429 — no new dependency.

**It does not stop sybil scraping.** More accounts, more quota. Registration friction (email verification or a captcha) is the missing piece and is not built.

Verified live end to end: 401 anonymous, 200 authenticated, 429 with the quota spent, text search unaffected. The throwaway account was deleted and the user count is back to 11 — **two** accounts, because a first registration attempt succeeded even though the response parse failed. Check for strays by email pattern, not by the id you happen to hold. The table is `app_user`, not `user`.

## 4. Eligibility, and a test that proved nothing

`decide()` ran the economics branches before the eligibility branch, so a parcel that is not dimensionally eligible with no variance path got an economics reason whenever its margin happened to be weak:

| same parcel | recommendation | reason |
|---|---|---|
| margin 5% | `economics_unattractive` | "below the 10% screening threshold **under current assumptions**" |
| margin 30% | `likely_pass` | "does not appear dimensionally eligible" |

The blocker flipped on a number irrelevant to why it fails, and "under current assumptions" invites retuning inputs that can never make it eligible. Reachable through `can_build_by_right = conforming is True and has_permitted_uses` — a district with no recorded permitted uses, or unknown dimensions (`conforming is None`, so the variance guard doesn't fire).

**`test_an_ineligible_parcel_without_a_variance_path_is_a_likely_pass` already existed and passed.** The `_decide` helper defaults `est_margin` to `STRONG_MARGIN + 0.05`. The test encoded the right intent and never varied the one dimension that broke it. Handoff 0048 §3's lesson, in a different shape: **ask which inputs a passing test does not vary.**

`DECISION_VERSION` → d3 rather than a silent recompute: this is decision logic, not an input correction, so old rows must stop claiming the current engine produced them. **Deliberately not a full sweep** — `_STALE_ONLY_PREDICATE` matches on both versions, so `--only-stale` after a decision bump selects every parcel in every market (~11.5h for `phl`) to fix 486 rows. The affected set is exactly enumerable, so those were recomputed and the rest heal lazily on read.

## 5. Absentee, measured

`is_absentee` did a raw substring test. OPA writes the location field joined and the mailing street split, so the drift is systematic:

```
2620 MCKEAN ST     2620 MC KEAN ST PHILADELPHIA PA 19145
429 MCCLELLAN ST   429 MC CLELLAN ST PHILADELPHIA PA 19148
3609 WINONA ST     3609 WINONA  ST PHILADELPHIA PA 19129     (double space)
```

Production sweep, 777,715 rows in ~6 minutes, against a `pre_absentee_distress` baseline:

| market | correction |
|---|---|
| `phl` | 235 × −15 and 2,302 × −10 = **2,537** — exactly the pre-measured set |
| `hbg` | **31** × −10 — same class (`20TH`/`20 TH`, `1209A`/`1209 A`) |
| `pgh`, `wlm` | 0 |

**A prefix rule was measured and rejected**: it newly mis-flagged 18 owner-occupiers whose mailing address carries a building range (`101-103 FEDERAL ST` for `103 FEDERAL ST`). Those are regression guards in the tests now.

**Two movements are not from the code, and both will recur.** 88 parcels at +10 and 12 at +5 came from a week of ingestion since the 08-24 sweep. The change cannot add points — normalising both sides preserves substring containment, so the new rule flags a strict subset of the old. Net `phl` leads went 32,534 → **32,541**, *up* 7: the corrections mostly removed parcels already below the threshold while drift added a few above it. **A sweep always drifts against its own baseline**; `years_since_last_sale` is `CURRENT_DATE`-relative, so parcels cross `long_tenure` purely with the calendar.

## 8. Things that will bite

**The nightly runs a full hour.** Measured today: `opa_properties_public` 04:08 → `sheriff_sale` 05:14 UTC. Handoff 0048 §8's timings ("stopping dead at 04:00:49", "ran through 04:03:24") are per-dataset and read like minutes. **Query `ingest_run` before every deploy** — every row wants a `finished_at`. Deploying at 05:57 was clear by 43 minutes; deploying at 04:30 on the old assumption would have repeated the 08-24 incident exactly.

**A recompute moves numbers that have nothing to do with your change.** The targeted verdict recompute shifted `opportunity_score` on 6 of 462 locally — input drift since each row was last computed, three of them because the deal no longer yields an `est_margin` so the neutral economics factor replaced a negative one. `decide()` cannot move that score; it is computed before `decide()` is called and never reads its result. **Say which movements your change can and cannot cause, and prove it structurally rather than by eyeballing counts.**

**A pre-measurement scoped to one market will miss the others.** The absentee measurement was `phl`-only, so `hbg`'s 31 arrived unannounced in the sweep. The fix was right for them; the number was presented without the qualifier it needed.

**Test doubles drift from the API they double.** The endpoint `_FakeRedis.sadd` took a single member while real Redis takes varargs. Passing tests would have hidden a production `TypeError`.

**A quota test that never fails proves nothing.** #189's endpoint test was confirmed red with the guard disabled before being accepted. Do this every time; §4 is what happens when you don't.
