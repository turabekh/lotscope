### 2.1 The contradiction sweep (#116, ADR-0076)

Four surfaces contradicted their own evidence. All four were measured through the real code path:

| surface | contradiction | scale |
|---|---|---|
| `VerdictPanel.vue` | "Variance likely" chip; three lines below, **"By-right units: 2"**, tooltip saying that is what the standards allow *without a variance* | **62,066 v8 parcels (27.2%)** |
| `reports/dossier.py` | the same bare count under a "variance likely" summary band, in the PDF users forward to lenders | same population |
| `checklist/logic.py` | **"Zoning conformance could not be determined"** on every special-purpose lot, while the hero said "Master plan" and the screening reason said a master plan is required | **1,372 — every master-plan parcel** |
| `VerdictHero.vue` + `VerdictPanel.vue` | master-plan status recovered by string-matching `"master plan"` in the verdict summary | structural |

**The cause is structural, not careless.** The posture rule existed in exactly one place — `zoning/program.py`, written for #114 — and four older surfaces re-derived it independently. `program.py` got every case right; the four that predate it did not, and nothing made the disagreement visible.

That re-derivation was **forced**. `requires_master_plan` is computed in `buildability.py`, consumed inside `compose_verdict`, then **discarded** — it is not on `ComposedVerdict`, not on `parcel_verdict`, not on `VerdictResult`. Two components had no way to recover it except by reading prose. A wording change in `_summary()` would have silently reverted 1,372 parcels to advertising units they cannot use, with every test green.

`zoning/posture.py` now owns the rule; `program.py`, the checklist, the PDF and both components consume it. Master-plan outranks every other signal. A unit count is never rendered bare — its label carries its condition ("Units if a variance is granted", "Units the standards would support"), and a master-plan lot renders `None`, never a number.

The posture is resolved **once per checklist response** from freshly assessed buildability, not the stored verdict. A stale verdict row disagreeing with a live program statement would reintroduce the same defect from the other side.

### 2.2 Stale decisions never healed (#117)

`get_or_compute_current_verdict` tested `verdict_version` alone. A row stored at the current verdict version but computed **before the screening contract existed** was therefore fresh forever: `recommendation` stayed NULL and the hero rendered **"Not yet screened"** indefinitely, while the checklist, program, risk and deal panels beneath it were fully populated. Same class, understating direction.

ADR-0072 assumed these would be picked up "at the next recompute". Nothing triggers one — the batch job recomputes unconditionally regardless of version, and the read path never noticed the decision was missing.

The freshness test now covers `decision_version`. Verified on `pgh:0019R00008000000`: `decision=None → d1` on a single read.

## 3. What the sweep cleared

Two surfaces in the original brief turned out to be clean. Both were checked by computing 300 spread-sampled phl parcels (`ORDER BY md5(parcel_number)`) through the real service, not by reading code:

- **Screening recommendation vs risk flags — 0 violations.** A single high-severity flag scores 40 against an elevated threshold of 60, so `strong_candidate` above a hard `fail` *is* reachable in principle. It did not occur once in 300 parcels, because parcels carrying such flags land in `high_entitlement_risk` or `economics_unattractive` first. **ADR-0072 considered this case and chose the reason-clause remedy deliberately — do not re-litigate it without new evidence.**
- **Program statement vs deal killers — 0 violations.** #114's `flagged_checks` already pulls from the risk categories, so the program's conditions name them.

`ChecklistSummary.ready` is computed and typed but rendered nowhere. Dead data, no false all-clear. Left alone rather than removed — that would be an unrequested refactor.

## 5. Process — what worked, what to keep

**Measuring first killed a hypothesis and found a better one.** The predicted screening contradiction did not exist; the sample instead exposed 20 parcels with no recommendation at all, which became #117. Reading `decide()` alone would have produced a fix for a defect nobody has.

**Reading the prior ADR before "fixing" its subject.** ADR-0072 had already considered "Strong candidate above risk flags" and chosen the reason clause. Two minutes of reading avoided reverting a deliberate decision.

**Every new test asserts the user-visible string.** The report tests decompress the PDF content streams with stdlib `zlib` and read the rendered text — the existing ones asserted the bytes start with `%PDF` and could never have caught the defect in the artefact users forward to lenders. No new dependency was needed.

**Verify the wiring, not just the component.** Component tests pass `checklist` as a prop directly, which would hide a dossier that never passes it. Checked `ParcelDossier.vue` separately.
