## 3. The deal and risk sweep (#124, unmerged)

### Risk: swept, nothing found

`RiskPanel` already qualifies its clear state — *"Nothing was found in liens, L&I, flood, or ownership records. That is what we checked — it is not a guarantee the lot is clean."* `DistressPanel` qualifies with *"on record"*. **No change needed.** Recorded as a result so the next sweep does not re-cover it.

### Deal: the same defect shape as #116, one field over

`analyze_deal` sets `infeasible` when the max allowable offer computes **below zero**, then floors that offer to `0`. The backend carries the flag on `DealResult`, `ScenarioItem` and the underwriting cases, and the **PDF renders a red `NEW BUILD NOT FEASIBLE` tag from it**. No frontend surface used it.

| surface | before |
|---|---|
| `DealPanel` | `Max allowable offer: $0`, bare |
| `ScenariosPanel` | infeasible rows identical to viable ones |
| `UnderwritingPanel` | `infeasible` typed but never read |
| PDF | already correct |

**107,230 verdicts** have `max_allowable_offer = 0` with an ARV present. On each, the panel said `$0` — which reads closer to *"free"* than to *"no price makes this work"* — while the PDF for the same parcel said the build is not economical at any land price.

**The sharpest end was the offer dialog.** `GenerateOfferDialog`'s no-economics guard is `maxAllowableOffer === null`; an infeasible deal carries `0`, so the guard never fired and it **seeded a letter of intent at $0**. Passing `null` when infeasible reuses the guard that already exists.

**That is the behaviour change to weigh before merging:** on 107,230 parcels, "Generate offer" now routes to the manual-price path instead of prefilling `$0`. Correct, but it is a user action, not a label.

Verified on real data: `pgh:0020E00100000000` → `infeasible=True mao=0.0 arv=337400 margin=-0.64`.

## 5. Operational facts

- **SSH to the VM works** (§1). For jobs: write the script to `/tmp`, `docker compose cp` into `worker`, run `docker compose exec -T worker python /tmp/<script>.py`, then clean up.
- **Never run a job while a deploy is in flight** — `compose up -d` recreates `worker` and kills it.
- **The seed never deletes.** It upserts on `(market_code, code, code_version)`; a stale reference row survives forever and needs a migration.
- **Hand-write every Alembic migration.**
- **Parking ships with the code, not the seed** — it is a module constant.
- Posture, buildability confidence, the program statement, the valuation band and parking are **all computed on read**. No recompute, no version bump when they change.
- **A missing openapi schema does not mean a missing field** (§3) — hand-built dict responses have no schema.
- **Do not start `make dev` as a harness background task** — both servers get SIGTERM'd at the turn boundary. `nohup … & disown` from a foreground call survives indefinitely.
- After a Docker restart, `mailpit` can fail `make up` with `network … not found`; `docker rm -f lotscope-mailpit-1`, then retry.
- Philadelphia zoning codes have **no hyphen** in `parcel` (`RSA5`) but **are hyphenated** in `zoning_standard` (`RSA-5`).
- The dossier route is `/parcel/<market-slug>/<parcel-number>`.
