### 2.1 The auth fix is the one that mattered

Reported as "odd behaviour when the token expires". Four faults, and the first explains the symptom:

- **The route guard checked `auth.token === null`.** An expired token is a non-empty string, so the guard let you in, the shell mounted, and every request then 401'd — you looked signed in and nothing worked.
- No central 401 handling, so callers swallowed 401 into empty state.
- Refresh ran on a blind 30-minute tick and no-opped silently on failure. Asleep past expiry meant a dead token that was never cleared — and `/auth/refresh` needs a *live* token, so it could not recover.
- `restore()` cleared the session on **any** error, so a network blip signed you out.

Now: expiry is read from the token (`lib/session.ts`), guard and `isAuthenticated` share one definition, refresh is scheduled from the real expiry with a ten-minute lead, and `restore()` only gives up on a 401.

**A 401 alone does not end the session.** The first version did that and broke the admin page — one panel's forbidden request signed the whole user out, worse than the original bug. It now verifies against `/auth/me` first, with re-entry guarded so a burst of failures verifies once.

**Verified in production**: an expired token lands on `/login?redirect=/philadelphia/pipeline` with the token cleared.

## 3. Process notes

**Three mistakes worth recording, all mine.**

**I committed directly to `main`.** After a squash-merge left me on `main`, I committed and pushed the dossier work there, bypassing branch-and-PR. Recovered by moving the commits to a branch and force-resetting `origin/main`. **After any `gh pr merge --delete-branch`, check what branch you are on before the next commit.**

**I wrote a test against a real local parcel.** `phl:324053201` exists on a developer machine and not in CI's fixture, so `e2e` failed. ADR-0071 records this exact trap in as many words. The fixture now seeds a sixth parcel with a long address so the case is owned by the test.

**A unit test reached a live API.** Two `FirstSteps` tests bypassed the file's own stubs, so `onMounted` fetched the watchlist. It passed locally *because my dev API was running* and failed in CI. Fixed, and **vitest now points `VITE_API_URL` at a dead port** so an accidental request fails immediately on a developer's machine. §12 forbids network in unit tests; nothing enforced it until now.

**One thing that keeps paying off: verify at the layer the user occupies.** Session 32 established it; this session confirmed it twice more. A `width` declaration that "obviously" applied was silently dropped by Quasar's own rule of equal specificity — found only by reading the computed style, not by trusting the CSS. And a production probe failed where **the app was right and the test was wrong**.
