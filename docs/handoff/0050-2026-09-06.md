## New machinery worth knowing about

| Thing | Where | Note |
|---|---|---|
| Analyst ceilings | `backend/src/lotscope/budget/` | `$3`/40 runs per user per day, `$50` global. Settings `analyst_daily_usd_per_user`, `analyst_daily_runs_per_user`, `analyst_daily_usd_global`, `analyst_global_alert_fraction`. |
| Per-account override | `app_user.analyst_daily_usd`, `.analyst_daily_runs` | Null = platform default, 0 = stopped. Set via `PATCH /admin/users/{id}`; explicit null clears. |
| Spend ledger | `analyst_usage(user_id, day, source, …)` | `source` is `chat` (what the per-user ceiling reads) or `job` (the nightly brief — counts on the invoice and against the global cap only). |
| Error capture | `backend/src/lotscope/core/observability.py` | Sentry if `SENTRY_DSN` is set, else `error_event` + a 15-minute digest. Fingerprint is exception type + **route pattern**. |
| Cron timetable | `backend/src/lotscope/ops/cron_schedule.py` | One list; the worker builds `cron_jobs` from it and readiness judges against it. A test fails if they drift. **Add a cron here, not in `worker.py`.** |
| Stale jobs | `stale_cron_jobs()` in `ops/service.py` | Two scheduled runs back. A job with history is judged from its own first appearance; one with none only if the worker outlived the window (`ops_alert_state` key `worker_started_at`). |
| Backups | VM crontab + `scripts/verify-backup.sh` | Nightly 03:00 UTC, 14-day retention; weekly restore-into-scratch at 03:30 Sunday writing `backup:restore_check` into `job_run`. |

## Lessons this session actually paid for

- **Three of the session's bugs were only visible in a real browser on production**, and
  two of them had been shipped and green for weeks: `/admin` blank since Phase 3 because
  a card read a field the API stopped returning *and the test's own mock supplied it*, and
  `/admin/jobs/runs` 500ing on any page holding a cron row. A fixture that returns a field
  the API does not is a fixture testing a server we do not run.
- **My own new stale-job rule was wrong on its first contact with production** — it called
  two just-added crons stale because "two runs ago" predated them. Shipping a monitor and
  then reading what it says is the only way that surfaces.
