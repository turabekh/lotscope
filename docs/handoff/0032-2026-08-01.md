### 6.3 What it caught — `display: none` beats a DOM query

The by-right qualifier shipped that same hour in #76 was **invisible on desktop**. `VerdictHero.vue` hides `.pillar-hint` above 1023px, so the only route to it was hovering a tooltip, and on a touch device there was no route at all.

**The component test passed because it stubbed `QTooltip`**, which rendered the tooltip body into the DOM where `wrapper.text()` found it. The test proved the string existed. It could not prove anyone could read it, and LR-B-002 requires the qualifier to *accompany* the claim — presence was never the bar.

Fixed in #80: the buildability card renders the qualifier as visible text on every viewport, pinned by a component test with `QTooltip` stubbed to render nothing, and an e2e `toBeVisible()`, which fails on `display: none` where a DOM query passes.

**The general lesson.** Stubbing a component in a test can make invisible content visible to the test. When a requirement is that a user *sees* something, assert visibility, not presence.

**The specific chain is worth remembering** — the same claim was checked three times, each one layer closer to the user, and each layer corrected the one before:

| Layer | Verdict | Truth |
|---|---|---|
| Keyword search over source | "no qualifier exists" | wrong — different wording |
| String present in the shipped bundle | "it shipped" | true, and irrelevant |
| Rendered page in a real browser | "invisible above 1023px" | correct |

Only the last one was worth anything.
