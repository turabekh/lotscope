| Comps **STOP-gated** — if the free GDB carries no sale price, escalate to a vendor (Regrid/ATTOM) or a Recorder scrape | **Gate cleared.** `SALEPRC`/`SALEYR`/`SALEMON` are on the same LUP layer (`_COMPS_FIELDS`). No vendor, no scrape, no sourcing decision needed. |
| Zoning resolved **by centroid against the City Zoning polygon layer**, with parcel `ZONECODE` as a cross-check | **Inverted.** `ZONECODE` is the *only* source (`_ZONING_FIELDS`). `zoning_district` has **0 wlm rows** and `resolved_zoning_source` is **NULL for all 26,197 parcels** — wlm bypasses the ADR-0056 deterministic-resolution path entirely and reads the parcel attribute. The `26` hundred-prefix normalization (`26R-3` → `R-3`, plus `26R3`/`OR` cleanup) shipped as planned in
`normalize_wilmington_zone`. Sheriff `countyId=24` shipped as planned.

**Net effect:** Wave 2 was substantially *cheaper* than ADR-0064 forecast. The ADR called comps "the
critical path, not zoning (the pgh inversion)" — in the event, comps were free and zoning took the
shortcut. Worth remembering when scoping Wave 3: the recon's pessimism about a county `.gov` WAF was
correct but irrelevant, because the *city* ArcGIS org carried the same fields openly.

## Honest degradation (PR #31)

`wlm` declares three `no_data_source` categories in `markets/capabilities.py` — these are structural
DE gaps, not pending loads, and the distinction matters for the graduation gate:

- **`li`** — code-enforcement/permits are portal-only (BuildingBlocks, MUNIS); no open dataset.
- **`liens_taxes`** — DE publishes delinquency as a state list, not parcel-level open data. Explicitly
  *not* a clean-title confirmation.
- **`access`** — no street-centerline data loaded; frontage/landlocked unconfirmed.

Plus `_RISK_COVERAGE_NOTE["wlm"] = "based on available Wilmington sources"` on the risk pillar, and
`zoning_standard` source `"Wilmington Zoning Code (Ch. 48)"`.

## The sale-year pivot bug (PR #34)

The one real defect the ingest surfaced. `_wlm_sale_date` pivoted two-digit `SALEYR` on a fixed
constant (`_SALE_YEAR_PIVOT = 40`), so upstream 27/28/29/31 became **2027–2031**, not 1927–1931 —
seven wlm sales with future dates.

Why that is not cosmetic: the comps query (`valuation/service.py:46`) bounds `sale_date` from **below
only** (`>= :since`, no upper bound), so a future-dated sale sits inside *every* lookback window and
surfaces as the freshest nearby comp. Three of the seven clear `DEFAULT_MIN_PRICE` (1000.0) and sit on
**vacant** parcels — the vacant-lot AVM that is the core product. A 1928 price ($2,500 / $5,000 /
$9,586) presented as a current comp.

Fixed by pivoting against a reference year (`date.today().year`, injected at the loader edge so the
resolver stays pure) instead of a constant. Chosen over simply lowering the constant to 26 because
that is correct today and silently wrong next year. Re-ingest verified: future-dated wlm sales
**7 → 0**; the three rows now read 1928. Four tests added, including one pinning the forward behavior.

**The unbounded upper bound in the comps query is still there** — this fix stops *wlm* from producing
future dates; it does not stop the query from trusting one. Any future loader with the same class of
bug lands the same way. Worth a follow-up.

## Gotchas

- **`_LOCAL_SRID = 2235` for wlm**, not 2272 — the first market off the PA plane. Any hand-written
  spatial SQL that assumed 2272 is wrong for Wilmington.
- **wlm zoning has no `zoning_district` polygons and no `resolved_zoning_source`** — it reads
  `base_zoning_code` off the parcel. Do not assume the ADR-0056 resolution path is populated for wlm.
- **`make seed` is not the full seed** (above).
- **Verdict recompute is market-scopable** (`verdict.jobs --market wlm`); distress, vacancy, and
  assemblage jobs are **not** — they run every market, ~740k parcels locally.
- **Local dev:** an unrelated `jungler` API can occupy `127.0.0.1:8000` and shadow lotscope; it was not
  running this session, so the API used the default 8000 and Vite served on **5173**.
- **Ingesting while recomputing is a trap** — the first verdict run straddled the comps fix, so early
  batches used the bad comps. Finish ingest, then recompute.
